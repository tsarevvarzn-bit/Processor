# Процессор

Реализация собственного виртуального процессора и ассемблера на си, позволяющих писать ассемблерный код, преобразовывать его с помощью ассемблера в байт код и выполнять с помощью процессора. 

# Как пользоваться
Скачайте репозиторий и разархивируйте его, перейдите в корневую папку Processor и скомпилируйте ассемблер и процессор:
```text
g++ .\Source\Assembler.cpp -o Assembler.exe
```
```text
g++ .\Source\Processor.cpp `                                                     
>>     -I".\Raylib" `
>>     -L".\Raylib" `
>>     -lraylib `
>>     -lglfw3 `
>>     -lopengl32 `
>>     -lgdi32 `
>>     -lwinmm `
>>     -o Processor.exe
```
Напишите программу на ассемблере в текстовом файле, поместите ее в папку AsmPrograms или воспользуйтесь одним из примеров, который там уже есть. Проассемблируйте код, чтобы его мог выполнять процессор:
```text
.\Assembler.exe -f AsmPrograms\YourAsmCodeFileName.txt -t ByteCodePrograms\YourByteCodeFileName.bin
```
Теперь программа готова для выполнения процессором, можно ее запустить:
```text
.\Processor.exe -f ByteCodePrograms\YourByteCodeFileName.bin
```

 ## Структура проекта
```text
Stack/
├── Common.h                       # Инклюд стандартных библиотек, общие константы, enum коды ошибок
├── DebugDefinition.h              # Макросы для включения/выключения различных проверок и защит
├── TypeDefinition.h               # Макросы для определения типа элемента стэка
├── Stack.cpp                      # Основные функции для работы со стэком
├── InputOutput.cpp                # Печать стэка
├── Protect.cpp                    # Проверка канареек, хэшей, общий верификатор и функции для расчёта хэша
├── .gitattributes                 # Настройки Git
├── .gitignore                     # Файлы и папки, игнорируемые Git
└── README.md                      # Документация проекта
```

## Фичность
- **Динамическое выделение памяти под стэк** для любого стэка память выделяется динамически как под саму структуру стэк, так и под массив элементов стэка, это даёт возможность удобно и быстро создавать несколько разных стэков с возможностью их полного удаления.
- **Автоматическое изменение размера стэка с гистерезисом** при попытке запушить данные в заполненный стэк вызывается функция stackResizeUp(), увеличивающая размер массива элементов в два раза, используя realloc(), если же пользователь пытается запопить элемент из стэка, в котором количество элементов в 4 раза меньше емкости, стэк аналогичным образом уменьшает свою емкость в 2 раза. За счет постоянного запаса при уменьшении стэка решается проблема "медленных размеров" стэка, при работе с которыми стэк будет постоянно увеличиваться/уменьшаться, что сильно увеличивает время работы программы.
- **Поддержка любого типа элемента** тип элемента, с которым работает стэк задается с помощью макросов в TypeDefinition.h, стандартно реализован char и double, при необходимости использования другого типа нужно просто написать для него свой блок макросов, в который будет определяться как этот тип печатается, вводится, каким для него определеяется ядовитое значение, а также функцию проверки на ядовитое значение.
- **Общий верификатор** полный верификатор, при вызове проверяющий переданный ему стэк на адекватность: ненулевые указатели, емкость не меньше размера, вызывается только при включенном флаге IS_COMMON_PROTECT
- **Канареечная защита** структура стэк и массив данных защищены 8-байтными канарейками с обоих сторон, каждая имеет свое уникальное значение, память под канарейки и их проверка происходит только при включенном IS_CANARY_PROTECT
- **Хэш защита** при изменении программой стэка пересчитывается хэш данных, кладется в структуру стэк, затем пересчитывается общий хэш структуры, включающий в себя этот стэк, что позволяет защититься от взломов, ошибок и любых изменений данных, которые делают не наши функции, память под хэши, их проверка и пересчет выполняется только при включенном IS_HASH_PROTECT
- **Гибкая, удобная, глубокая система проверок** - все проверки настраиваются тремя флагами IS_COMMON_PROTECT IS_CANARY_PROTECT IS_HASH_PROTECT, при включении хотя бы одного из них перед и после работы любой функции вызывается проверка структуры по включенным методам проверки. Если все флаги ноль - стэк максимально быстрый, никаких проверок не происходит, если все флаги включены - постоянно проверяются все функции верификации, проверяющие стэк разными независимыми методами
- **Подробный красочный printStack (см примеры вывода)** - при включенных проверках каждый шаг в консоль выводится подробный отчет о состоянии стэка, включая канарейки и хэши (если соответственный режим включен), при нахождении ошибки верификаторами выводится еще более подробный отчет, содержащий данные о причине и месте ошибки
