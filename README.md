# Процессор

Реализация собственного виртуального процессора и ассемблера на C, позволяющих писать ассемблерный код, преобразовывать его с помощью ассемблера в байт код и выполнять с помощью процессора. 

# Как пользоваться
Скачайте репозиторий и разархивируйте его, перейдите в корневую папку Processor и скомпилируйте ассемблер и процессор:
```text
g++ .\Source\Assembler.cpp -o Assembler.exe
```
```text
g++ .\Source\Processor.cpp -I".\Raylib" -L".\Raylib" -lraylib -lglfw3 -lopengl32 -lgdi32 -lwinmm -o Processor.exe
```
Напишите программу на ассемблере в текстовом файле, поместите ее в папку AsmPrograms или воспользуйтесь одним из примеров, который там уже есть. Проассемблируйте код, чтобы его мог выполнять процессор:
```text
.\Assembler.exe -f AsmPrograms\YourAsmCodeFileName.txt -t ByteCodePrograms\YourByteCodeFileName.bin
```
Теперь программа готова для выполнения процессором, можно ее запустить:
```text
.\Processor.exe -f ByteCodePrograms\YourByteCodeFileName.bin
```

- **Вычислительный стек** все вычисления процессора основаны на вычислительном стеке (структура данных, основанная на приницпе LIFO), импортирующемся в проект как билиотека, подробнее о нем можно узнать в моем репозитории Stack на гитхабе, я использую именно его. Каждый элемент стека - число double, для работы со стеком используются 2 базовые команды: PUSH - положить число в конец стека и POP - безвозвратно удалить последнее запушеннное в стек число, получив его значение
- **Регистры** процессор имеет 4 double переменные для быстрого и удобного доступа к ним по именам: AX, BX, CX, DX - при PUSH'е значения из регистра, его значение не меняется, это позволяет расширить возможности процессора
- **Стек возврата** аналогично вычислительному стеку, в процессоре существует стек, хранящий индексы байт кода, на которые стоит прыгнуть при вызове RET, что позволяет реализовать вызов функций и рекурсивные алгоритмы
- **Оперативная память** массив переменных типа double, к которым можно обращаться по их номерам, увеличивает объем данных, с которыми может работать процессор
- **Видеопамять** блок оперативной памяти, находящийся в ее начале, значение которого используется при рисовании картинки командой DRAW

- **Отступы** в начале любой строки можно использовать символы пробела и табуляции, ассемблер их проигнорирует и правильно обработают команду
- **Пустые строки** пустые строки ассемблер так же будет пропускать и игнорировать, корректно обрабатывая следующие за ними комманды
# Команды ассемблера
- **PUSH ARG** - кладет в вычислительный стек процессора число
  - **PUSH 3.14** - положить константу
  - **PUSH AX** - число, лежащее в регистре AX
  - **PUSH BX + 4** - значение AX + 4
  - **PUSH [10]** - значение 10й ячейки оперативной памяти
  - **PUSH [DX]** - значение ячейки оперативной памяти с номером DX
  - **PUSH [CX + 7]** - значение ячейки оперативной памяти с номером CX +7
- **POP ARG** - забирает число из вычислительного стека процессора
  - **POP AX** - кладет в регистр AX
  - **POP [10]** - в 10-ю ячейку оперативной памяти
  - **POP [DX]** - в ячейку с номером значения DX
  - **POP [CX + 7]** - в ячейку с номером значения DX + 7
 >[!WARNING]
 >При обращении к элементу оперативной памяти по номеру, дробная часть номера отбрасывается
- **JUMP ARG** выполнение программы "перескакивает" на указанные индекс байт кода, который может быть задан явно (**JUMP 10**) или с помощью метки (**JUMP :mark1**) - рекомендуется использовать способ с метками как более явный. Другие версии JUMP'ов перескакивают только при выполнении некоторого соотношения между последними двумя элементами из вычислительного стэка

   - **JA** более "глубокое" число больше последнего, запушенного в стек
   - **JAE** больше либо равно
   - **JB** меньше
   - **JBE** меньше либо равно
   - **JE** равно
   - **JNE** не равно
>[!WARNING]
>Все JUMP'ы безвозвратно берут 2 элемента из стека
- **CALL ARG** позволяет безусловно перепрыгнуть на индекс ARG (может быть как меткой, так и числовым индексом), аналогия JUMP. При этом запоминая индекс байт кода, где был вызван, записывая это значение в стек возврата. При вызове RET код возвращается к выполнению кода в том месте, где был вызван CALL (на следующую за CALL команду).
- **RET** берет последнее значение из стека возврата и реализует безусловный JUMP по этому индексу
- **IN** ожидает ввода пользователя в консоль double числа, пушит его в вычислительный стек
- **OUT** выводит число из вычислительного стека в консоль
- **DRAW** визуализирует видеопамять, выводя ее текущее состояние
- **DELAY ARG** процессор останавливает свою работу на ARG секунд, затем продолжая с того же места
- **HLT** оставновить процессор
- **ADD** взять из стека 2 числа, сложить, результат вернуть в стек
- **SUB** вычесть более глубокое из последнего запушенного в стек
- **MUL** переменожить
- **DIV** поделить более глубокое на последнее
- **SQRT** взять корень из последнего в стеке числа, результат положить в стек
- **RND** округлить лежащее в вычислительном стеке число, отбросив целую часть

## Фичность
- **Максимальная скорость** благодаря разделению ассемблера и процессора, процессор не занимается парсингом программы и лишними вычислениями, все проверки и подставноки делаются только один раз при ассемблировании программы, благодаря чему процессор выполняет минимальное количество действий максимально быстро
- **Сложная система синтаксиса** благодаря отступам, пустым строкам и комментариям писать код на ассемблере гораздо удобней, с помощью них можно отделять куски кода и писать заметки о работе программы
- **Массив указателей на функции в процессоре** при получении следующей команды, процессор обращается в массив команды по полученному номеру команды, максимально быстро, без циклов
- **Гибкий дебаг процессора** вывод данных о работе процессора гибко настраивается несколькими флагами компиляции: COMMANDS_DUMP, PROC_STRUCT_DUMP и CONSOLE_DRAW, каждый можно включать/отключать независимо
- **Метки и двухпроходное ассемблирование** благодаря двухпроходному ассемблированию в ассемблерном коде можно задавать метки любыми именами `:mark_name` и пользоваться ими при вызове функций и джампов `JUMP :mark_name`
## Полнота
Процессор и ассемблер в связке дают возможность написать огромный спектр различных программ и алгоритмов и запустить их. Ассемблерный язык позволяет реализовать любой возможный вычислительный алгоритм (Тьюринг полный), используя при этом понятные и простые конструкции.
